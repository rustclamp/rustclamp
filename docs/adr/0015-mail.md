# ADR 0015: Mail

Status: Accepted, 2026-09-30.

## Context

Phase 11 C gives `rustclamp` apps outgoing mail. The house rules (`~/projects/CLAUDE.md`) require three layers on every send path before it ships: a per-route throttle, a daily cap per app that queues over the cap and releases at reset, and recipients bound to an authenticated user, a signed URL or a verified address. The fleet sends through Brevo's SMTP relay (`smtp-relay.brevo.com:587`, STARTTLS), and that account is shared by jobly.si, dppbase, placaj and after.si: one abused form can exhaust the quota for all of them.

Decided with Lex on 2026-09-30: SMTP over rustls, a cap of 100 per day, and a throttle of 3 per minute on sending routes.

## Decision

- **An optional `mail` feature** (`db` + `config`) with `rustls` (0.23, `default-features = false`, features `ring`, `std`, `tls12`) and `webpki-roots` (1.x). This is **not pure Rust**: the `ring` provider compiles C and assembly with `cc`, as the bundled SQLite already does. The default `aws-lc-rs` provider is avoided because it needs cmake. The dependencies are listed in `tools/boundaries.py` and stay optional.
- **Every send goes to an outbox.** `Mailer::send` only inserts a row into the framework-owned `mail_outbox` table. A background thread started by `web::App::run` delivers pending mail at startup and then once a minute, oldest first. A visitor never waits on Brevo, and an SMTP outage never becomes a 500. `App::test` starts no thread; tests call the delivery step directly with a given day.
- **Layer 2, the daily cap** (`MAIL_DAILY_CAP`, default 100) is counted in the database per UTC day, over mail the server accepted. Claiming a row is atomic (one statement moves it from `queued` to `sending` only while today's count is under the cap), so 32 worker threads cannot overshoot. Over the cap, mail stays queued and goes out after midnight UTC; the first time the cap is hit each day is logged as a warning with the queue size. Failed deliveries stay queued with an attempt count and a backoff, and are never dropped.
- **Layer 3, recipients by type.** `Recipient` has no conversion from a string. It is built from a config key (such as the site owner's address) or from an authenticated `auth::User`. A value from a request cannot become a recipient; a `compile_fail` doctest proves it. CR and LF are refused in addresses, names and subjects.
- **Layer 1** stays the route's `Throttle`; routes that send mail default to 3 per minute.
- **SMTP client** (std `TcpStream`): multi-line replies; EHLO again after STARTTLS; with `MAIL_ENCRYPTION=tls` a server that does not offer STARTTLS is an error, never a plaintext fallback; AUTH over plaintext only with an explicit `MAIL_ENCRYPTION=none` (a local Mailpit); SNI and certificate checks against `webpki-roots`; timeouts on connect, read and write. Messages are UTF-8 with base64 bodies and RFC 2047 encoded headers, so Slovenian text needs no 8BITMIME. The password and message bodies are never logged.
- **Config** uses Laravel's names: `MAIL_MAILER` (`smtp` or `log`, default `log`), `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_ENCRYPTION`, `MAIL_FROM_ADDRESS`, `MAIL_FROM_NAME`, `MAIL_DAILY_CAP`, read by the app's `config/mail.rs`.

## Consequences

Mail is delivered up to a minute late. Production hosts need the `MAIL_*` keys added to their existing `.env` by hand, because the Ansible playbooks write `.env` only on first provisioning. Phase 11 B2 must not loosen layer 3: verification and reset mail goes to an address someone just typed, so it will use signed URLs with their own throttle and count against the same cap.
