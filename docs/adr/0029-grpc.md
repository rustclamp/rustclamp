# ADR 0029: gRPC

Status: Accepted, 2026-10-07.

## Context

Stage 7 (Integrations) lists gRPC. An app that already serves Axum routes through `rustclamp-http` should be able to serve a `tonic` service too, without a second listener, a second server loop or a second shutdown path. tonic's generated servers are already Tower services, so the work is mounting one, not wrapping it.

## Decision

- **An optional `grpc` feature on `rustclamp-http`** (rustclamp/http#13). It adds `tonic` (no default features, only `codegen`) and turns on `axum/http2`. The default build stays free of tonic, prost and h2.
- **`HttpRoute::grpc(service)`** contributes a generated `FooServer` like any other route: `HttpRoute::<Public>::grpc(GreeterServer::new(greeter))`. It becomes the route `/package.Service/{*method}` (the name comes from tonic's `NamedService`), so a duplicate service, or a route or mount inside that prefix, fails the build with the usual `RouteBuildError`. It is a catch-all route, not `mount`: Axum's nesting strips the prefix, and the generated service matches on the full path.
- **One listener for both protocols.** With `http2` on, `serve` (`axum::serve`) answers HTTP/1.1 and cleartext HTTP/2 (h2c, prior knowledge) on the same port. The existing layers (request context, body limits, rate limit) wrap gRPC calls too, and graceful shutdown drains them with everything else.
- **Unknown methods answer gRPC `Unimplemented`.** A known service answers its own unknown methods. An unknown service gets Axum's 404, which gRPC clients map to `Unimplemented`.
- **No `protoc`.** The integration test hand-writes the few lines `tonic-prost-build` would generate for one prost message. Apps generate their code however they like (`tonic-prost-build`, or `protox` for a pure-Rust build).
- **Not included:** TLS (terminate at a proxy, as for HTTP), gRPC-Web, server reflection, health service, and compression. Each is a tonic layer or extra service an app can add itself, and each waits until an app needs it.

## Consequences

`rustclamp-http`'s dependency allowlist grows by tonic's closure (h2, tonic, prost for tests). The default feature set is unchanged. Because gRPC shares the Axum router, middleware written for HTTP responses (problem+json errors, 401/403) answers gRPC callers with HTTP status codes, which tonic clients map to gRPC codes (`Unauthenticated`, `PermissionDenied`) but without a gRPC message.
